# GWEH 정보구조 재설계 — 홈 화면 + 드릴인

- 작성일: 2026-07-30
- 선행: `2026-07-29-ui-redesign-design.md` (완료, 머지됨 `50d974d`)
- 범위: 내비게이션 구조와 화면 내 정렬. 기능·로직 무변경.

## 1. 문제

사용자 보고: "UI가 삐딱하다", "메뉴구조·버튼위치 등 전체적인 UI 개편".
실기기 iPhone(420px CSS) 스크린샷이 근거다.

### 1.1 탭 8개가 라벨 없는 이모지다

`Navigation.tsx:48`이 `hidden sm:inline`이므로 **라벨은 640px 이상에서만 렌더된다.**
420px 기기에서는 이것만 보인다:

```
☯️  🔮  👔  👁️  💖  ✋  🏛️  📊
```

🏛️가 사주, 👁️가 관상, 💖가 궁합임을 알아낼 방법이 없다. 스크린리더 사용자는
`sr-only` 라벨을 받으므로 오히려 **눈으로 보는 사용자가 더 불리하다.**

### 1.2 같은 일을 두 번 하고 있다

`HeroSection.tsx:16-21`이 서비스 카드 6개를 렌더하고, `handleServiceClick`(`:27`)이
실제로 탭을 전환한다. 각 카드에는 `labelKey`와 **`descKey`가 이미 정의돼 있다** —
설명은 렌더되지 않을 뿐 존재한다.

즉 홈 화면 역할을 하는 그리드와 탭바가 공존하며 같은 목적지로 간다.

### 1.3 직전 개편이 이걸 놓친 이유

`2026-07-29` 개편은 정확성(대비·키보드·내비게이션 동작)과 일관성(프리미티브·토큰)을
고쳤다. 감사가 모바일 레이아웃을 "건강함"으로 판정해 보존했는데, 그 판정의 근거는
`scrollWidth === 390`이었다. **"가로 스크롤이 없다"는 "쓸 만하다"가 아니다.**
정보구조는 한 번도 검토 대상이 아니었다.

### 1.4 화면 내 정렬 결함 (스크린샷)

| 결함 | 원인 |
|---|---|
| `<input type="date">`가 카드 오른쪽 경계를 넘어감 | iOS Safari의 date input은 고유 너비를 가지며 `w-full`로 축소되지 않는다. flex/grid 자식의 기본 `min-width:auto`가 축소를 막는다 |
| 날짜는 중앙정렬, 바로 아래 시간 선택은 좌측정렬 | 두 입력의 정렬 규칙이 다르다 |
| "7일 무료 체험" 배너가 우하단에 부유하며 콘텐츠와 겹침 | `SubscriptionBanner`가 `fixed bottom-6 right-6` |

**이 계열이 자동 측정을 통과한 이유**: Chrome의 date input은 iOS Safari보다 좁다.
헤드리스 Chrome으로는 재현되지 않는다. 실기기 스크린샷이 유일한 검증 수단이었다.

## 2. 설계

### 2.1 홈 화면 = 승격된 서비스 그리드

새로 만들지 않는다. `HeroSection`의 그리드를 진짜 내비게이션으로 만든다.

```
현재                            바뀐 뒤
──────────────────────────     ──────────────────────────
히어로 (서비스 카드 6개)   ①    홈 = 서비스 카드 8개
탭바 (라벨 없는 이모지 8개) ②      아이콘 + 이름 + 한 줄 설명
콘텐츠                             ↓ 탭
                                 서비스 화면
                                   헤더에 ← 뒤로
```

| 변경 | 파일 | 내용 |
|---|---|---|
| 서비스 6 → 8 | `HeroSection.tsx:16-21` | `omen`·`summary` 추가. `ServiceIcon`에 아이콘 2종 추가 |
| 설명 렌더 | `HeroSection.tsx:108` | 이미 있는 `descKey`를 라벨 아래 표시 |
| 그리드 2열 | `HeroSection.tsx:101` | `grid-cols-3` → `grid-cols-2 md:grid-cols-4`. 3열은 카드가 좁아 설명이 들어가지 않는다 |
| 탭바 제거 | `Navigation.tsx` 삭제, `App.tsx` | 이모지 8개 문제가 구조적으로 사라진다 |
| 뒤로 가기 | `AppHeader.tsx` | 서비스 화면일 때만 `←`. 홈에서는 로고 |
| `home` 상태 | `src/lib/tabs.ts` | 기존 3분기 해시 규칙에 홈을 추가 |

**서비스가 9개가 되어도 카드 하나만 늘리면 된다.** 탭을 몇 개까지 넣을 수 있는지
고민할 필요가 사라지는 것이 이 설계의 핵심 이득이다.

### 2.2 라우팅

`src/lib/tabs.ts`는 이미 세 경우를 구분한다 — 초기 로드 미인식 해시, `hashchange`
빈 해시, `hashchange` 비탭 해시. 여기에 홈을 추가한다.

```
해시 없음 / #home        →  홈
#saju 등 유효 탭          →  해당 서비스
초기 로드, 미인식 해시     →  홈 (기존: DEFAULT_TAB)
hashchange, 빈 해시       →  홈
hashchange, 비탭 해시     →  현재 화면 유지 (인페이지 앵커)
```

`DEFAULT_TAB`은 `'omen'`에서 `'home'`으로 바뀐다. `App.tsx`의
`Record<TabId, TabRenderer>`가 컴파일 타임에 누락을 잡으므로 `home`을 추가하면
렌더러도 강제된다.

**뒤로 가기는 이미 동작한다** — `hashchange` 리스너가 있다. 홈이 히스토리 항목이
되므로 서비스에서 브라우저 뒤로가기를 눌러도 홈으로 온다.

### 2.3 화면 내 정렬

| 대상 | 처리 |
|---|---|
| `SajuTab.tsx:302` date input | `min-w-0`을 추가해 축소를 허용한다. `w-full`만으로는 iOS Safari의 고유 너비를 이기지 못한다 |
| 날짜/시간 정렬 | 둘 다 좌측 정렬로 통일. 값 길이가 달라 중앙정렬은 세로로 어긋나 보인다 |
| `SubscriptionBanner` | `fixed bottom-6 right-6`를 콘텐츠 흐름 안으로 옮긴다. 부유 배지가 CTA와 겹치는 것은 Task 5·7 리뷰에서도 지적됐다 |

`min-w-0`은 다른 flex/grid 자식 입력에도 필요한지 확인한다 — 같은 원인의 다른 사례가
있으면 함께 처리한다.

## 4. 검증

직전 개편의 교훈을 반영한다. **자동 측정만으로는 이 계열이 안 잡힌다.**

| # | 검증 | 통과 기준 | 수단 |
|---|---|---|---|
| I1 | 홈에서 8개 서비스가 이름과 설명과 함께 보인다 | 420px에서 8개 전부, 이름·설명 잘림 없음 | **실기기 스크린샷** |
| I2 | 서비스 진입·복귀 | 카드 탭 → 해당 화면, `←` → 홈, 브라우저 뒤로 → 홈 | 브라우저 |
| I3 | 탭바 부재 | `Navigation` 참조 0건 | grep |
| I4 | date input이 카드 안에 있다 | 입력 우측 경계 ≤ 카드 우측 경계 | **실기기 스크린샷** |
| I5 | 날짜·시간 정렬 일치 | 두 입력의 텍스트 시작 x좌표 동일 | **실기기 스크린샷** |
| I6 | 구독 배너가 콘텐츠를 가리지 않는다 | CTA와 겹침 0 | **실기기 스크린샷** |
| I7 | 가로 스크롤 회귀 없음 | 8개 화면 `scrollWidth === clientWidth` | 헤드리스 |
| I8 | 게이트 | 대비 38/38, 타입 18 known/0 new, 빌드 성공 | 명령 |

**I1·I4·I5·I6은 실기기 스크린샷으로만 확정한다.** 헤드리스 Chrome은 iOS Safari의
폼 컨트롤 렌더링을 재현하지 않으며, 그것이 이번 결함들이 28커밋을 통과한 이유다.

## 5. 구현 순서

```
1. tabs.ts 에 home 추가 + App.tsx 렌더러        → I2 일부
2. HeroSection 을 홈으로 (8개·설명·2열)          → I1
3. AppHeader 에 뒤로 가기                       → I2
4. Navigation 제거                             → I3
5. 정렬 3건 (date·정렬·배너)                    → I4·I5·I6
6. 회귀 확인 + 실기기 스크린샷                   → I7·I8
```

1~4가 구조, 5가 정렬이다. 5는 1~4와 독립이므로 순서를 바꿔도 되고, 급하면 5만
먼저 배포해도 된다.

## 6. 리스크

| 리스크 | 대응 |
|---|---|
| 탭바 제거로 서비스 간 이동이 느려진다 | 홈이 한 번의 뒤로가기 거리에 있다. 실제로 불편하면 서비스 화면 하단에 "다른 서비스 보기"를 추가 |
| 히어로가 홈이 되면서 첫인상이 바뀐다 | 히어로는 저장소에서 가장 잘 만들어진 컴포넌트다. 카드 2개 추가와 설명 표시 외에는 건드리지 않는다 |
| `DEFAULT_TAB` 변경이 기존 북마크를 깨뜨린다 | `#omen` 등 기존 해시는 그대로 동작한다. 바뀌는 것은 해시가 없을 때의 착지점뿐 |
| `min-w-0`이 다른 곳을 깨뜨린다 | 대상 입력에만 적용하고 I7로 가로 스크롤 회귀를 확인 |
