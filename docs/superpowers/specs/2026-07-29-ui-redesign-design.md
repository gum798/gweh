# GWEH UI 개편 설계

- 작성일: 2026-07-29
- 기반 감사: 6개 영역 병렬 감사, 약 110건 (모든 수치는 실측·재검증)
- 범위: UI 전면 개편. 기능 변경 없음.
- 선행 작업: `docs/superpowers/specs/2026-07-28-error-recovery-design.md` (장애 복구, 완료)

## 1. 문제 정의

사용자 표현은 "UI도 구리네"였다. 감사 결과 원인은 색이 아니었다.

### 1.1 진짜 원인 — 앱 셸이 없다

`App.tsx:145`가 `<HeroSection>`을 콘텐츠와 **형제**로 렌더한다. 히어로가 곧 헤더다. 여기서 모든 것이 파생된다.

| 증상 | 근거 |
|---|---|
| 탭 누를 때마다 865px 위 히어로 안으로 | `App.tsx:57` `window.scrollTo({top:0})` — 히어로가 생기기 전에 쓰인 코드 |
| 뒤로가기가 URL만 바꾸고 화면은 그대로 | `hashchange`/`popstate` 리스너 **0건** (전 저장소 확인) |
| 언어 전환·로그인이 히어로에만 존재 | `HeroSection.tsx:50-83`. `i18n.changeLanguage` 호출이 트리 전체에 1회뿐 |
| 네비가 1280px에서 x=208의 864px 섬 | `Navigation.tsx:25` `sticky top-0`이 `App.tsx:152`의 `max-w-4xl px-4` 안에 갇힘 |
| 640~869px 영어에서 **기본 탭이 도달 불가** | `Navigation.tsx:26` `justify-center` + `overflow-x-auto` → 음수 스크롤 영역으로 밀림. "racle"로 잘림 |
| 8개 중 6개 탭이 **두 번째 히어로**를 렌더 | `OmenTab:318`, `FaceTab:133`, `PalmTab:109`, `FortuneTab:303`, `SajuTab:227`, `FashionTab:395` — 페이지 헤더가 없어 각자 만듦 |

### 1.2 두 번째 원인 — 토큰 계층이 뒤집혀 있다

토큰화된 것은 의미를 거의 안 나르는 계층이다: radius(198/203 준수), shadow(109/113). 정작 의미를 나르는 것이 없다 — `fontSize` 없음, `letterSpacing` 없음, 상태색 없음.

결과: 폰트 크기 18종에 임의값 `text-[Npx]` 36개. 원시 팔레트 직접 사용 114곳, 8개 색상군. 성공이 `green-*`과 `emerald-*` 두 가지, 경고가 `orange-*`/`amber-*`/`yellow-*` 세 가지. 같은 "대길"이 탭마다 다른 앰버로 렌더된다(`FortuneTab:176-180`, `SajuTab:413-419`, `SummaryTab:320-328`, `OmenTab:465-470` 인라인).

**그리고 가장 많이 쓰는 색 세 개가 WCAG AA에 미달한다:**

```
gal-accent  #2ea3f2   2.75:1  ❌   텍스트 110곳 + 버튼 채움 ~60곳
gal-muted   #999999   2.85:1  ❌   126곳 (큰 글씨 기준 3:1 도 미달)
gal-border  #e5e5e5   1.26:1  ❌   99곳. 흰 카드를 흰 배경에서 구분하는 유일한 수단
```

선택된 탭이 제품에서 대비가 가장 낮은 글자다(2.50:1, 비선택 2.85:1보다 낮음).

`src/lib/themes.ts` + `applyTheme.ts`는 134줄에 CSS 변수 27~30개를 정의하고 `main.tsx:11`에서 부팅 시 실행되지만 **소비자가 0건이다**(`var(--` 사용 0건, 확인됨).

### 1.3 세 번째 원인 — 공용 컴포넌트 계층이 없다

탭 8개, 5,558줄이 같은 것을 각자 구현한다.

```
버튼   41개  →  서로 다른 클래스 조합 29가지 (파일 간 재사용 5가지뿐)
카드   54개  →  25가지
로딩          →  같은 "분석 중" 순간에 6가지
카드 패딩     →  p-4 / p-5 / p-6 / p-8 / p-10
```

"이 카드가 중요하다"를 `border-gal-accent` / `border-gal-accent/20` / `border-gal-border` 세 가지로 표현하며 규칙이 없다. `SummaryTab`에서는 동급 결과 카드 4개 중 3개가 파랑, 1개가 회색이다(`:432/478/523` vs `:542`).

`FaceHarmonyTab.tsx`가 극단이다 — 780줄, **`t()` 호출 0건**(나머지 7개 탭은 18~48회). 영어 사용자에게 이 탭만 한국어로 나온다. 설정에 없는 파란색 3개를 직접 박아 놓았고(`:92`), 혼자 다른 여백 체계(`mx-2`/`mx-4`)를 쓰며, `max-w-md`가 없어 카드가 ~830px로 벌어지는데 정작 자기 리셋 버튼(`:572`)에는 `max-w-md`가 있어 같은 화면에서 어긋난다.

### 1.4 네 번째 원인 — 인터랙티브 요소가 컨트롤이 아니라 마크업이다

사진 업로드 타깃 5개가 `tabIndex`·`role`·키 핸들러 없는 맨 `<div onClick>`이고, 각자 프록시하는 `<input type="file">`은 `className="hidden"`이다. **키보드 사용자는 패션·관상·손금·궁합에 사진을 넣을 수 없다**(`CameraCapture.tsx:308,316`, `FashionTab.tsx:480,509`, `FaceHarmonyTab.tsx:662,672`).

모달 2개 모두 `role="dialog"` 없음, 포커스 트랩 없음, 복원 없음. `aria-live`/`role="status"`/`aria-expanded`가 `src/` 전체에 0건. 포커스 링은 버튼 73개 중 14개.

`CameraCapture.tsx:251-260`의 `<Webcam>`이 종횡비를 예약하지 않아 UA 기본 300×150으로 렌더됐다가 스트림이 붙으면 304×304로 점프한다 — **사용자가 촬영 버튼으로 손을 뻗는 바로 그 순간에 154px 리플로우**가 일어난다.

### 1.5 다크/화이트 충돌은 원인이 아니다

두 감사자가 독립적으로 "FINE"으로 분류했다. `HeroSection.tsx:156`의 그라디언트는 y=753~865의 실제 112px 전환이며 `#app-content` 경계(`App.tsx:152`, y=865)에 정확히 착지한다. 최악의 결함은 `via-white/50`이 `#060a14` 위에 얹히는 ~40px 회색 띠이며 5분 작업이다.

히어로는 저장소에서 **가장 잘 만들어진 컴포넌트**다 — 1.5 스트로크로 통일된 손그림 24×24 아이콘 6개, cubic-bezier 스태거 리빌, 장식 레이어마다 `aria-hidden`, 실제 그라디언트 핸드오프.

**결론: 히어로를 흰색으로 칠해도 여전히 저대비에 네비게이션 적대적이고 세 가지 디자인 언어로 된 앱이 남는다. 균일하게 흰색일 뿐이다.**

### 1.6 유지할 것

| 항목 | 근거 | 처분 |
|---|---|---|
| 간격 체계 | `src/` 전체 임의 spacing 값 **0건** | 손대지 않는다 |
| radius·shadow 토큰 | 198/203, 109/113 준수 | 값만 다크에 맞게, 이름 유지 |
| 탭 본문 모바일 레이아웃 | 390×844에서 8개 탭 전부 `scrollWidth == 390` | 손대지 않는다. `md:` 누락은 **데스크톱** 문제 |
| `SajuTab` | `:426/454/470/491` 동일 카드 5개, 양쪽 CTA에 포커스 링, `t()` 34회 | **수렴 기준 템플릿** |
| `HeroSection` | 위 참조 | 구조 위치만 바꾸고 내용은 유지 |

## 2. 방향

`design/screen.png`·`design/code.html`의 **다크 퍼플 미스틱**으로 전환한다. 이 방향은 구독자 메일(`worker.ts`, `#5b13ec` 10곳 + `#161022`)에 이미 살아 있어, 전환하면 메일→앱 여정의 정체성이 처음으로 일치한다.

**단, 순서를 뒤집는다.** 공용화를 먼저 하고 토큰을 나중에 교체한다.

지난 7번의 리디자인이 전부 "색만 바꾸고 구조는 두고 가기"였고, 그래서 지금 버튼 스타일이 29가지다. 공용 컴포넌트가 없는 상태에서 방향을 바꾸면 29곳을 다크로 재작업한 뒤 공용화하며 또 만져야 한다. 공용화를 먼저 하면 다크 전환이 **토큰 파일 2~3개 수정**으로 끝나고, 다음 방향 변경도 같은 비용이 된다.

## 3. 설계

### 3.1 팔레트 — 액센트를 두 역할로 분리

현재의 근본 실수는 액센트 하나(`#2ea3f2`)를 채움과 텍스트에 동시에 쓴 것이다. 채움으로 괜찮은 색이 텍스트로는 2.75:1이 된다. 다크로 옮기며 이 구조를 반복하면 안 된다.

| 역할 | 값 | 용도 | 대비 |
|---|---|---|---|
| **채움** `accent` | `#5b13ec` | 버튼 배경, 배지, 강조 블록 | 흰 글씨 **7.64:1** ✅ |
| **잉크** `accent-ink` | `#a78bfa` | 링크, 아이콘, 강조 텍스트 | base 위 **6.82:1** ✅ |

`#5b13ec`는 레퍼런스와 메일이 이미 쓰는 값이라 브랜드가 유지된다. 같은 색상각의 밝은 변형만 추가하는 것이다. **레퍼런스의 `#5b13ec`를 텍스트로 쓰면 `#161022` 위에서 2.43:1로 실패**하므로(계산 확인), 잉크 역할을 반드시 분리해야 한다.

**서피스 4단계**

```
--bg-base     #161022   페이지 배경 (레퍼런스 그대로)
--bg-surface  #1e1630   카드·패널
--bg-raised   #2a1f42   모달·팝오버·호버
--border      #3a2f52   카드 경계 — 지금 1.26:1 이던 것을 실제로 보이게
```

**텍스트 3단계** (전부 AA 통과)

```
--text-primary    #f6f6f8   17.20:1  ✅  (레퍼런스 그대로)
--text-secondary  #b8b0c8    9.1:1   ✅
--text-muted      #8b8299    4.8:1   ✅  ← 지금 2.85:1 이던 자리
```

**상태색 4종** `success` / `warning` / `danger` / `info` 를 토큰화한다. 현재 `green`/`emerald`, `orange`/`amber`/`yellow`로 흩어진 것을 하나로 모으고, 세 곳에 복제된 운세 등급 표를 단일 `LevelPill`로 통합한다.

**모든 값은 AA 4.5:1 이상을 만족해야 한다.** 구현 시 대비 계산 스크립트로 검증하며, 미달 값은 채택하지 않는다. 이번 감사가 찾은 결함의 상당수가 "검증 없이 고른 색"이었다.

### 3.2 앱 셸

가장 레버리지가 큰 변경. **탭 파일 8개를 하나도 건드리지 않고 8개 탭 전부의 경험을 고친다.**

- `App.tsx:57`의 `window.scrollTo({top:0})` 삭제. 대신 콘텐츠 상단으로 스크롤한다.
- `hashchange` 리스너 추가 → 뒤로가기 복구.
- `<Navigation>`을 `App.tsx:152`의 `max-w-4xl px-4` 밖으로 들어올려 **풀블리드 sticky 바**로 만든다.
- `Navigation.tsx:26` `justify-center` → 넘칠 때 `justify-start`, 들어갈 때만 중앙 정렬. 기본 탭 도달 불가 해소.
- **상설 헤더** 신설: 브랜드 + 언어 토글 + 인증. `HeroSection.tsx:50-83`에서 이동. 히어로를 지나도 언어 전환과 로그인이 가능해진다.
- 스킵 링크 추가 (현재 네비 앞에 포커스 가능 요소 11개).

### 3.3 공용 프리미티브

`SajuTab`의 레시피로 수렴한다.

| 컴포넌트 | 대체 대상 | 목표 |
|---|---|---|
| `<Button>` | 버튼 클래스 29가지 | **4가지** (primary / secondary / ghost / danger) |
| `<Card>` | 카드 25가지 | **3가지** (base / accent / muted) |
| `<PageHeader>` | 탭별 히어로 6개 + 제각각인 제목 | 1가지 |
| `<LoadingState>` | 로딩 화면 6가지 | 1가지 |
| `<LevelPill>` | 운세 등급 표 3벌 + 인라인 1 | 1가지 |

터치 타깃은 `OmenTab.tsx:444`의 **44px 최소**를 전역 채택한다(현재 네비 40×42px).

### 3.4 타이포그래피

`fontSize`·`letterSpacing` 스케일을 `tailwind.config.js`에 추가하고 임의값 `text-[Npx]` 36개를 치환한다.

폰트는 라틴 **Space Grotesk**(레퍼런스), 한글 **Noto Sans KR**(현행 유지). 현재 `index.html:38-40`이 400/500/700만 로드하는데 코드는 `font-light`(300)·`font-semibold`(600)를 22곳에서 쓴다 — 실제로는 400/700으로 렌더된다. 로드하거나 사용을 제거하거나 둘 중 하나로 정리한다.

### 3.5 브랜드 통일

`GWEH AI`로 통일한다. 근거: 저장소명·도메인이 `gweh`, 가장 최근 디자인 작업(`50a79d2`)의 선택.

교체 대상: `index.html:10,11,18,23,29,62`(MYSTIC AI ×6), `worker.ts`(Mystic AI ×2, MYSTIC AI ×1), `OmenTab.tsx:326-329`의 세 번째 `<h1>`(기본 탭 첫 화면에 MYSTIC/AI를 렌더) 및 대응 로케일 키 `omenTab.heroTitle1/2`.

**브랜드 문자열을 한 곳에 상수화**하여 다음 변경이 1줄이 되게 한다.

부수 정리: `public/favicon.svg`가 어느 팔레트와도 안 맞는 금색(`#d4af37`) → 액센트 계열로 교체. `index.html:7` `theme-color: #ffffff` → `#161022`. 누락된 `og-image.jpg` 생성. `robots.txt`가 가리키는 sitemap 확인.

### 3.6 접근성

- 사진 업로드 `<div onClick>` 5곳 → `<button>`. 키보드로 사진 제출이 가능해진다.
- 모달 2개에 `role="dialog"` + 포커스 트랩 + 포커스 복원.
- 토스트·로딩에 `aria-live`.
- 포커스 링을 `<Button>` 프리미티브에 내장하여 73개 전체에 적용.
- `prefers-reduced-motion` 대응 (현재 명명 애니메이션 14종에 대응 0건).
- `CameraCapture`의 `<Webcam>`에 종횡비 예약 → 154px 리플로우 제거.

### 3.7 히어로

내용은 유지하고 **구조 위치만** 바꾼다. 페이지 레벨 형제에서 "한 번 스크롤해 지나가는 것"으로 강등한다. 탭별 두 번째 히어로 6개는 `<PageHeader>`로 대체하며 삭제한다.

`min-h-screen` → `min-h-dvh`. 현재 CTA 하단이 iPhone SE(667px) 뷰포트에서 y=694, 영어에서 y=716로 **화면 밖**이다. 스크롤 큐가 `text-white/15`(1.56:1)로 자기 그라디언트 형제에 덮여 있는 것도 함께 고친다.

## 5. 검증 방법

테스트 러너가 없으므로 측정 가능한 기준으로 대체한다.

| # | 검증 | 통과 기준 |
|---|---|---|
| U1 | 대비 | 토큰 전 조합이 AA 4.5:1 이상 (스크립트 계산) |
| U2 | 탭 전환 | 탭 클릭 시 콘텐츠 상단에 착지, 히어로로 되돌아가지 않음 |
| U3 | 뒤로가기 | 브라우저 뒤로가기가 이전 탭을 실제로 표시 |
| U4 | 기본 탭 도달 | 640px·869px 영어에서 첫 탭이 잘리지 않고 클릭 가능 |
| U5 | 버튼 수렴 | 버튼 클래스 서명 29 → 4 이하 (grep 카운트) |
| U6 | 카드 수렴 | 카드 변형 25 → 3 이하 |
| U7 | 임의값 | `text-[Npx]` 36 → 0 |
| U8 | 브랜드 | `MYSTIC` 문자열 0건 (문서 제외) |
| U9 | 키보드 사진 업로드 | Tab·Enter로 4개 탭 전부 파일 선택 가능 |
| U10 | 모바일 | 390×844에서 8개 탭 `scrollWidth == 390` 유지(회귀 방지) |
| U11 | 히어로 | iPhone SE 667px에서 CTA가 화면 안 |
| U12 | 빌드·타입 | `npm run build`, `npm run typecheck` 신규 에러 0 |

U10이 중요하다 — 현재 정상인 것을 개편이 깨뜨리지 않는지 확인한다.

## 6. 구현 순서

```
1. 토큰 확장        fontSize·letterSpacing·상태색 추가 (값은 아직 화이트)  → U7, U12
2. 앱 셸            scrollTo·hashchange·네비 풀블리드·상설 헤더             → U2, U3, U4
3. 공용 프리미티브   Button/Card/PageHeader/LoadingState/LevelPill          → U5, U6
4. 탭 수렴          8개 탭을 프리미티브로 치환, 두 번째 히어로 제거          → U5, U6, U10
5. 접근성           업로드 버튼화·모달·aria-live·포커스 링·reduced-motion    → U9
6. 다크 전환        토큰 값 교체 + 히어로 조정                             → U1, U11
7. 브랜드·자산      이름 통일·favicon·og-image·theme-color                 → U8
```

1~5는 **화이트 테마 상태로 배포 가능**하다. 6에서 비로소 다크가 된다. 각 단계가 독립적으로 사용자에게 보이는 개선을 낸다.

순서의 핵심은 6이 마지막이라는 것이다. 3~4를 먼저 끝내야 다크 전환이 토큰 교체로 끝난다.

## 7. 리스크

| 리스크 | 대응 |
|---|---|
| 탭 8개 수렴 중 시각 회귀 | U10으로 모바일 회귀 방지. 단계별 프리뷰 배포로 육안 확인 |
| 다크 전환 시 이미지·차트 가독성 | 5개 탭이 Unsplash 이미지를 쓴다. 오버레이 조정 필요 |
| `SajuTab` 템플릿이 모든 탭에 안 맞을 수 있음 | 프리미티브에 variant를 두되 4/3개 상한을 지킨다 |
| 브랜드명 결정 번복 | 문자열을 상수화하여 1줄 변경으로 만든다 |
| 개편이 장애 복구 검증을 방해 | 미완 검증(V5~V12)은 별도 스펙 소관. UI 변경은 API 계약을 건드리지 않는다 |
